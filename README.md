# Experience in Morocco

A Morocco travel **marketplace**: local suppliers (tour operators, guides, activity providers, artisans, transport companies) list their tours and experiences; travellers browse, filter and send booking requests. The agency runs the site and can list its own tours too. Hotels, accommodation and restaurants are not part of it.

- **Travellers** send a booking request (date, time, travellers, package, pickup… depending on the experience) and get the answer by email. An account is optional: **Sign in** (top bar) → **My bookings** shows their requests, offers and confirmations, and lets them cancel.
- **Suppliers** sign up at `/supplier/join`, complete their business profile, add listings with a 7-step form made for their type of experience, and answer requests in their dashboard (`/supplier`): send an offer, confirm, decline, mark completed. Their listings wait for the agency's approval (can be switched off).
- **The agency** approves suppliers and listings in wp-admin, sees every booking request in **Inquiries** (emails for suppliers' listings go to the supplier), and answers requests for its own listings.

### Categories and launch phases

17 categories in 6 menu groups (Tours, Adventure, Desert Experiences, Culture & Local Life, Food & Wellness, Events & Workshops), each with its activity types and its own form, mapped to 7 listing types that decide what travellers are asked when booking:

| Listing type | Booking asks for | Categories |
| --- | --- | --- |
| Multi-day package | date, adults, children | Multi-Day Tours |
| Scheduled excursion | date, time, adults, children | Day Trips, City Tours, Local Guides |
| Timed activity | date, time, participants, option | Desert Adventures, Outdoor Adventures, Water Sports, Wellness, Family Activities |
| Class or workshop | date, session, seats | Food & Culinary, Cultural Experiences, Arts & Crafts, Sports |
| Experience package | package, date, participants | Desert Camps & Experiences, Unique Experiences |
| Event or ticket | event date, ticket type, quantity | Events & Entertainment |
| Transfer | route or pickup/drop-off, time, passengers, flight, luggage | Private Transfers |

Suggested launch: phase 1 multi-day tours, day trips, city tours, desert activities (camel, quad, buggy), Agafay and Merzouga experiences; phase 2 cooking, Amazigh culture, hiking, surf, hammams, workshops, food tours; phase 3 family activities, sports, festivals, unique experiences, transport. All categories are available from day one; the phases are about which suppliers to recruit first.

The whole listing engine (categories, activity types, fields, required/optional, conditions, menu groups, onboarding checklist, filters) is one file, `backend/wp-content/plugins/travel-agency-core/data/listing-schema.json`, generated by `backend/scripts/build-listing-schema.py` and used by both WordPress and the app.

```
backend/    WordPress (Docker) + "Travel Agency Core" plugin → REST API at /wp-json/travel/v1
frontend/   React + TypeScript + Vite single-page app
*.html      Original static HTML template (unchanged)
```

## Install without the WordPress uploader

If WordPress answers "Incompatible Archive", it could not open the uploaded file. Usual causes: the host's upload limit or disk quota, or an incomplete download. Install through your hosting's **File Manager** (cPanel, hPanel, Plesk) instead:

1. Open File Manager and go to `public_html/wp-content/themes/`.
2. Upload `moroccotravely-theme.zip` there, select it and click **Extract**. You should get a folder `moroccotravely` (if one already exists, rename it to `moroccotravely-old` first).
3. In wp-admin → Appearance → Themes, activate **Experience in Morocco**. Delete the zip and the old folder afterwards.
4. Same for the plugin: upload `travel-agency-core.zip` to `public_html/wp-content/plugins/`, extract it (replacing the old `travel-agency-core` folder), then open wp-admin → Plugins.

## Install on your WordPress site (2 zip files)

1. **Plugin:** wp-admin → Plugins → Add New → **Upload Plugin** → choose `travel-agency-core.zip` → Install Now → **Activate**. The demo content (tours, day trips, activities, categories with photos, About Us, FAQs, policies, menus and example Agency details) is imported automatically.
2. **Theme:** wp-admin → Appearance → Themes → Add New → **Upload Theme** → choose `moroccotravely-theme.zip` → Install Now → **Activate**.
3. Settings → **Permalinks** → choose **Post name** → Save (pretty URLs such as `/tour/…`).
4. Settings → General → set **Site Title** (shown in the header and footer) and **Administration Email Address** (receives booking requests).
5. Agency details → replace the example email, address and social links with yours.
6. Optional, **Sign in with Google** for travellers: in [Google Cloud Console](https://console.cloud.google.com/apis/credentials) → Create credentials → OAuth client ID → type **Web application** → add your site address (e.g. `https://marruecosrutas4x4.com`) under **Authorized JavaScript origins** → Create. Paste the **Client ID** in Agency details → **Google sign-in** and save. "Continue with Google" then appears on the sign-in page.

To re-import the demo later: Agency details → **Demo content** → Import demo content.

Build the two zips from this repository with `./scripts/build-wordpress-zips.sh` (needs Node 20+); they are written to `release/`.

## Quick start

### 1. Backend (WordPress)

Requires Docker.

```bash
cd backend
cp .env.example .env
docker compose up -d
```

Open http://localhost:8080, finish the WordPress install, then:

```bash
docker compose run --rm wpcli wp plugin activate travel-agency-core
docker compose run --rm wpcli wp rewrite structure '/%postname%/'
docker compose run --rm wpcli wp eval-file /scripts/seed.php   # demo content (also imported on first activation)
```

### 2. Frontend (React)

Requires Node 20+.

```bash
cd frontend
cp .env.example .env      # points at http://localhost:8080/wp-json/travel/v1
npm install
npm run dev               # http://localhost:5173
```

Without a `.env`, the frontend runs on built-in sample data, so you can work on the design without WordPress.

## Managing the site (wp-admin)

Sign in at `/wp-admin` with your WordPress admin account. Travellers never see it.

| Menu | What you can do |
| --- | --- |
| **Agency details** | **Review supplier listings before they go live** (on by default). Email, phone, WhatsApp and address (Contact Us page and footer), the footer's **About us** text and **Accepted payment** list, the **Show prices** switch (untick to show "Price on request" everywhere; to hide one tour's price, tick **Hide price** on that tour), and your **social media**: Facebook, X, Instagram, Pinterest and LinkedIn (icons in the footer only). Empty a link to remove it. |
| **Users** | Suppliers have the **Supplier** role; the **Supplier** column shows their verification and number of listings. Open one to see the business profile and documents, set **Verification** (Verified / Changes needed, with a note; the supplier is emailed) or **Suspend** them (row action). |
| **Listings → Pending** | Listings submitted by suppliers. The **Supplier listing review** box shows who sent it and anything missing: click **Publish** to put it live (the supplier is emailed), or write a note and tick **Send back to the supplier**. A supplier who edits a live listing sends it back here. |
| **Inquiries** | Every booking request and contact message, with **Status** (Waiting for reply, Offer sent, Confirmed, Declined, Cancelled, Completed, Contact message), **Listing**, **Traveller**, date and guests. Filter with **All statuses**. Open a booking request and use **Answer this request**: pick Confirmed or Declined, write a reply and keep **Email the traveller** ticked to send it. |
| **Listings** | Your tours, day trips and activities, with **Photo** and **Price** columns. Add or edit one: set its **Listing category**, the **Featured image** and **Gallery photos** (both from the Media Library), the **Tour details**, and the **Itinerary (day by day)**: one block per day with a title, a description written with the text editor and the driving distance/time. The tour page shows: tour style badge, overview with duration / start / end / style, highlights, itinerary, important notes, included / not included, gallery, a Google map of the route (from the **Location label**, e.g. `Marrakech → Merzouga → Fes`), the FAQs and related tours. Tours live at `/tour/<slug>/`. |
| **Appearance → Menus** | Three menus: **Main menu** (top menu; drag an item under another to make a dropdown), **Orange tab links** (the tab under the menu and the footer's bottom bar) and **Footer links** (footer "Useful links"). Add pages, tours, Listing categories or custom links, rename and reorder them. Links to other sites open in a new tab. |
| **Pages** | About Us, FAQs (each `Heading 2` is a section and each `Heading 3` a question; they also appear on every tour page), Booking & Cancellation Policy, Privacy Policy, Terms & Conditions. Edit the text here; the app shows the published version. The legal pages are drafts: review them (ideally with a lawyer) before going live. |
| **Comments** | Traveller reviews. New reviews wait for approval; approving one updates the listing's rating. |
| **Listing categories** | Destinations (Morocco Tours From …), Day Trips, Activities and their sub-types. Each category can have a **Photo** (Media Library), shown on the home page city cards. |

Booking requests (and cancellations) for a supplier's listing go to **that supplier's email only**; tick **Send me a copy** in Agency details → Booking requests to receive copies. Requests for your own listings and contact messages go to the **Administration Email Address** in Settings → General. Every request is listed under **Inquiries** either way. Use **Agency details → Send test email** to check that your hosting delivers WordPress emails (otherwise install an SMTP plugin such as WP Mail SMTP).

The agency name in the header and footer is `SITE_NAME` in `frontend/src/config.ts`.

## API (`/wp-json/travel/v1`)

| Method | Route | Notes |
| --- | --- | --- |
| GET | `/tours` | `search`, `category`, `min_price`, `max_price`, `min_rating`, `sort`, `page`, `per_page`, and the filters `duration_type`, `city`, `tour_style`, `activity_level`, `booking_type`, `experience_style`, `languages`, `traveler_types`, `time_of_day`, `accessibility`, `included_services` (comma-separated values), `free_cancel`, `date` (runs that weekday) |
| GET | `/tours/{slug}` | Full listing: description, highlights, itinerary, inclusions, gallery, `fields` (every field of its category), `listingType`, `subtype`, `supplier` |
| GET | `/suppliers/{slug}` | Public supplier profile and live listings |
| GET / POST | `/tours/{id}/reviews` | POST is held for moderation |
| GET | `/tour-categories` | Categories with their `parent` |
| GET | `/pages/{slug}` | A published WordPress page: `{slug, title, content}` |
| POST | `/inquiries` | Booking request with `details` (time, option, package, ticket, quantity, pickup, dropoff, flight, luggage, adults, children); emailed to the supplier and the agency |
| POST | `/auth/register`, `/auth/login`, `/auth/forgot` | Supplier accounts; return `{token, user}` |
| POST | `/auth/traveller/register`, `/auth/traveller/login` | Traveller accounts; return `{token, user}` |
| GET / POST | `/auth/config`, `/auth/google` | Google Client ID; sign in with a Google ID token `{credential, as: traveller\|supplier}` |
| GET / POST | `/me`, `/me/bookings`, `/me/bookings/{id}/cancel` | The signed-in traveller and their booking requests (Bearer token) |
| GET / PUT | `/supplier/me` | Business profile, checklist, verification (Bearer token) |
| POST | `/supplier/uploads`, `/supplier/verification`, `/supplier/password` | Photos, logo and documents; request verification; change password |
| GET / POST | `/supplier/listings` | Own listings; create a draft `{category, subtype, title}` |
| GET / PUT / DELETE | `/supplier/listings/{id}` | Edit `{title, description, category, subtype, values, coverId, galleryIds}` |
| POST | `/supplier/listings/{id}/submit` · `archive` · `restore` · `duplicate` | Submit checks every required field |
| GET / POST | `/supplier/bookings`, `/supplier/bookings/{id}` | Requests for own listings; answer `{status, quote, reply, note}` |
| POST | `/contact` | Contact form `{name, email, phone, subject, message}`; stored in Inquiries and emailed to the agency |
| GET | `/settings` | Agency contact details and social links |
| GET | `/menus` | The theme's menus (`primary`, `quick`, `footer`) as trees of `{title, url, external, children}` |

Public POST routes are validated, rate-limited and have a honeypot field. CORS allows only `FRONTEND_ORIGIN`.

## Running the marketplace (wp-admin → Marketplace)

The red number next to **Marketplace** counts what is waiting for you.

wp-admin is the platform's dashboard: the team manages businesses, clients and listings, but doesn't list experiences or answer booking requests. Staff land on Marketplace after signing in. Its menu holds **Requests and businesses**, **Clients**, **All listings** (review only, no "Add" button), **Booking activity** (read-only: each request shows the business that answers it) and **Listing categories**. In marketplace mode, staff accounts can't use the supplier dashboard.

- **Business requests:** businesses that asked to be verified, with their website, page link, contact, legal details and documents. Click **Approve business**, or write a note and click **Ask for changes**. The business gets an email either way.
- **Listing requests:** listings businesses submitted. Click **Approve and publish**, or write a note and click **Send back for changes**. The business gets an email either way.
- **All businesses:** every business with its status, listings (live / waiting / draft), website and page on the platform.
- **Listings in our name:** listings that belong to the platform, not a business. With **marketplace mode** on (Agency details, on by default), they are hidden and can't be booked, so every booking request goes to a business. Move each one to the right business, or delete it.

## Accounts and security

- **Suppliers and travellers never get into wp-admin.** If they sign in at `wp-login.php` or open any `/wp-admin/` page, they are sent to their own dashboard (`/supplier` or `/account`). The WordPress toolbar is hidden for them. Only staff (editors and administrators) can use wp-admin.
- **Forgot password:** "Forgot your password?" on `/supplier/login` and `/signin` emails a link to `/reset-password` on the site. The link works once and expires after 24 hours. The answer is always "check your email", so nobody can find out which emails have accounts. Staff accounts don't get links this way: staff reset at `wp-login.php` as usual.
- **Passwords:** at least 8 characters, with letters and a number. Passwords that are too common, or that are the account's email, are refused.
- **Brute force:** after 5 wrong passwords an account is locked for 15 minutes. Each connection is also limited in how many sign-ins, sign-ups and reset emails it can send.
- **Sessions:** resetting or changing a password signs out every other device. Both dashboards also have a "Sign out other devices" button.
- **Supplier sign-up:** a website address is required (at sign-up and in the business profile). The registration number (RC / ICE), legal name, permits and documents are optional.
- **One business, one name:** the business name must be the same as the website name (`atlas-trekking.ma` → "Atlas Trekking"; case, spaces and hyphens don't matter). Two suppliers can't use the same business name or the same website.
- **Logo:** every business needs a logo (a required setup step), the same as on its website. In Business profile, **Use the logo from my website** finds it on their site (an image named or marked "logo", then the site icon) and saves it; they can also upload it. PNG, JPG and WebP are supported (not SVG). The logo shows on listing cards, the listing page, the business page and in Marketplace, where the team checks it matches the website.
- **Supplier page:** every supplier has a page at `/provider/<business-name>` with their profile and live listings. The dashboard shows the link with Copy and View buttons. Renaming the business changes the link.
- **Travellers** can edit their name and phone, change their password and delete their account under My bookings. Suppliers can't delete their own account (listings and bookings depend on it); ask the team.

## Production notes

- Travellers can book without an account; with one (`/signin`), their requests appear in My bookings (`/account`), matched by account or by email.
- Not built yet (next phase): online payment and payouts, an availability calendar with live seats, supplier replies to reviews, and in-site messaging. Today suppliers manage dates with operating days and blocked dates, and talk to travellers by email.

- Set `FRONTEND_ORIGIN` to your real site URL (comma-separate several).
- Configure SMTP (e.g. an SMTP plugin) so inquiry emails are delivered.
- Prices in the sample content are estimates: set your own in wp-admin.
- Photos: the demo import puts its photos in the Media Library as featured images. Other demo tours show placeholder photos from picsum.photos until you set a featured image.
- `npm run build` with `VITE_MEMORY_ROUTER=1 npx vite build --base ./` makes a build that works without server URL rewrites (used for the hosted preview).
- `npm run build` outputs static files in `frontend/dist`; serve them with a fallback to `index.html` so routes like `/tours/...` work.
